I checked all 15 settings state items across the 3 samples and found two blockers. Most screens follow the system well.

- **Toast covers the save buttons (2 of 3 samples).** The "Saved" toast sits over the action row. On desktop it hides most of the "Save changes" label; on phone it cuts off the bottom of both buttons. The spec says where a toast goes but not that it must stay clear of content, so I marked it as spec-caused.
- **Revoke buttons collapse on phone (1 of 3 samples).** On the password-mismatch screen, the Revoke buttons in the stacked sessions list shrink to a thin box and the word spills out over the border. The spec already says tables reflow into stacked blocks, so this is the sample's own bug.

Everything else holds: color bands, pink focus halos, error borders, hard-shadow dialogs, ink focus rings, and one pink action per screen.

The spec contradicts itself on switches: the interaction table says a selected switch fills pink, but two other rules say a selected control is never pink. All 3 samples used ink, which matches the stricter rule. The checklist has no item for this, so it isn't in the findings.
