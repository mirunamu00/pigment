2. **major**, signature, 1 of 1 sample(s)
   - Principle to fix: Choose pink per state, not per component. An action that stays on screen in a page header, band or toolbar (refresh, export, share, settings) is always lift--ink or lift--ghost, never pink, whatever state the page is in. Pink goes only to the one action the current state is about: the form submit, an empty-state or error recovery, a dialog confirm, or the page's main CTA. A component that brings its own button (empty state, error panel, toast) may make it pink only when no other pink button can be in the same viewport. Add a required Verification step: render every captured state at the desktop viewport in each theme and count the pink-filled buttons. There must be at most one, not counting small price or status tags. If any state shows two, the build is not done.
